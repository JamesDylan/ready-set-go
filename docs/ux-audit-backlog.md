# Ready Set Go — UX Audit & Product Backlog

> Generated by UX research agent — full end-to-end audit of signup, kid setup, daily routines, and parent settings.

---

## 1. Current User Journeys

### 1a. First-time Parent Setup
1. Auth via Supabase (`/auth` → `/onboarding`)
2. **Step 1 — Welcome**: Brand intro, single CTA
3. **Step 2 — Add Children**: Name, age band (little/school/independent), avatar, evening target time per child
4. **Step 3 — Routines**: Task selection (currently uses first child's age band for ALL children — see C1). Morning target set here as a shared value.
5. **Step 4 — All Set**: Preview + "Finish" → writes to store → pushes to `/`
6. On first load: `AvatarPickerModal` appears per child if `avatarConfirmed: false`

### 1b. Daily Morning Routine (Kid)
1. App auto-detects morning (hour < 14 on load), shows KidCards
2. Child taps task → debounced 500ms, tick sound + mini confetti
3. All done → completion sound + `CelebrationOverlay` full-screen (6s or tap to dismiss)
4. "Amazing, [name]!" banner shows inline
5. CountdownBar shows nearest upcoming school target

### 1c. Daily Evening Routine (Kid)
1. Mode auto-detects or parent toggles → evening tasks load
2. Per-child bedtime shown in card header
3. CountdownBar shows next upcoming bedtime (earliest child)
4. Celebration mechanics identical to morning

### 1d. Parent Managing Settings
1. Tap lock icon → PIN gate (default: 1234)
2. `ParentPanel` (82vw × 85vh modal) with sections:
   - **Kids**: CharacterAvatar, Edit routine / Remove per kid, Add kid
   - **Today's Routines**: Reset Day
   - **Streaks**: Per-child morning/evening counts, weekend toggles, Reset All
   - **PIN**: Placeholder ("coming soon")
   - **Lock + Sign out**

## 2. UX Issues — Severity Prioritised

### 🔴 Critical

**C1: All children share the same task list after onboarding**
- `src/app/onboarding/page.tsx` lines 81–125
- `handleFinish` applies `selectedMorning`/`selectedEvening` — derived from child 0's age band — to ALL children. A 4-year-old and 10-year-old get identical tasks.
- Fix: Per-child task selection in Step 3.

**C2: PIN hardcoded to '1234' with no change mechanism**
- `src/store/useAppStore.ts` line 231
- Anyone who discovers the default PIN has permanent parent access. "PIN management coming soon" is a placeholder.
- Fix: Add `pin` field to store, add change-PIN UI to parent panel.

**C3: ~~Reset Day destroyed all customisation~~ (FIXED)**
- Was calling `getEmptyDayData()` which replaced children with hardcoded seed data + zeroed streaks.
- Fixed: Now only clears `isComplete` flags on current children's tasks.

**C4: ~~Morning countdown used only first child's target~~ (FIXED)**
- Was `children[0].morningTarget`. Fixed to use nearest upcoming target across all children.

---

### 🟠 High

**H1: Onboarding task selection uses first child's age band for all children**
- `src/app/onboarding/page.tsx` line 31: `const firstBand = slots[0]?.ageBand ?? 'school'`
- Step 3 seeded from child 0 only — misleads parents into thinking it's personalised.

**H2: Onboarding does not set per-child morning target times**
- All children get the same `morningTarget` from Step 3. Evening targets are per-child (Step 2) but morning is not.

**H3: No confirmation dialog for Reset Day or Reset All Streaks**
- Both are fire-and-forget. Should have a brief confirmation step.

**H4: No way to rename a child or change their avatar after onboarding**
- Only "Edit routine" and "Remove" in parent panel. Name typo = remove and re-add (losing streak).

**H5: CelebrationOverlay per-child blocks all other cards**
- `src/components/dashboard/KidCard.tsx` line 89
- Full-screen `zIndex: 50` overlay fires per child. Three children finishing = 3 sequential full-screen interruptions, blocking sibling cards.

**H6: No undo for accidentally removed child**
- Two-tap confirm pattern but no undo after confirmation. All data permanently lost.

---

### 🟡 Medium

**M1: Mode auto-detection overwrites persisted mode on every cold load**
- `src/app/page.tsx` lines 49–54. Effect unconditionally calls `setMode`, discarding any manually set mode on refresh.

**M2: RoutineEditor uses ▲▼ buttons, not drag-to-reorder**
- Moving task from position 7 to 1 = 6 taps. Should use touch-friendly drag (`@dnd-kit/core`).

**M3: CountdownBar silently disappears when all evening bedtimes pass**
- No "All kids should be in bed!" message. Bar just vanishes.

**M4: No streak introduction for new users**
- First streak appears immediately ("1 day streak!") with no explanation of what it is.

**M5: ~~Dead localStorage write in onboarding~~ (FIXED)**
- `localStorage.setItem('ready-set-go-onboarding', ...)` was never read anywhere. Removed.

**M6: ~~COLOUR_MAP broken for dynamically added children~~ (FIXED)**
- Was keyed by colour name ('griff', 'harriet'). Fixed to key by `avatarType`.

**M7: `completedThisSession` disappears on page refresh**
- `src/components/dashboard/KidCard.tsx` line 25. In-memory state — "Amazing!" banner gone after refresh.

**M8: No animation when ParentPanel opens after PIN entry**
- Panel just appears instantly. Should fade/slide in.

---

### 🔵 Low

**L1: Reset Day requires 3 taps from parent panel** (lock icon → unlock → Reset Day)

**L2: Task `order` values become non-contiguous after deletion**
- `src/store/useAppStore.ts` — sort still works but values drift.

**L3: CountdownBar window hardcoded at 120 minutes**
- `src/components/dashboard/CountdownBar.tsx` line 21. No urgency signal until < 2 hours.

**L4: CelebrationOverlay copy identical for morning and evening**
- `src/components/routine/CelebrationOverlay.tsx` line 87. "READY SET GO! 🏁" plays for evening too.

**L5: Add Child doesn't navigate to routine editor immediately**
- Should call `handleEditRoutine(newId)` after adding.

**L6: Version label hardcoded "v1.0" in parent panel footer**
- Will drift from package.json.

## 3. Information Architecture Gaps

- **No global nav** — single-screen app; all parent management in a modal. Will not scale.
- **Streak context hidden from children** — no history, no milestones, no narrative. Kids don't know what they're building toward.
- **ModeToggle unexplained** — no label for children; wrong mode = wrong tasks.
- **No re-onboarding path** — no "reset and start over" from parent panel.
- **ParentPanel is a flat scroll** — Kids + Today + Streaks + PIN + Lock all in one area, no sub-nav.
- **Evening lacks distinct visual language** — uses same urgency colours (green/amber/red) as morning rush.

## 5. Missing Features That Seem Obvious

| Feature | Why It's Expected |
|---------|------------------|
| Task "skip today" option | Sick days, parent exemptions — currently requires editing the routine |
| Routine templates / preset packs | Summer, school holidays, sports day |
| Task time estimates | Helps parents know if routine is achievable in remaining time |
| Child "I need help" signal | Critical for youngest users (age 4) — Griff specifically |
| PIN recovery | Essential before PIN change ships; tie to Supabase re-auth |
| Offline resilience message | Supabase auth expiry at 6:30am = broken app at worst moment |
| Task notes / parent annotations | "Put the green container in your bag today" |
| Print-friendly routine card | Families complement digital with physical fridge checklist |
| Sibling completion leaderboard (opt-in) | Drives engagement for older children |
| Custom colour themes per child | Colours locked to avatar type — not all kids identify with assigned colour |
